# 文字／數字優先審核與效能改善

日期：2026-10-15。使用者確認本專案以找出文字、數字及表格內容修改，供人工審核為核心。

## 已實作

- 主要清單、頁面標註及「內容差異／已審／待審／內容問題」統計只包含內容項目。文字修改與數值修改分開計算，含有相同數字的文字改寫歸為文字修改。
- 尚無可靠文字解釋的影像候選獨立列為「辨識待確認」，預設收合，可展開查看原始裁切與位置；仍需人工核對，不當成沒有修改，也不自動提升為高風險。
- 移除介面固定的 95% 信度與「確有結構變更」文案。待確認區域使用「確認已核對」，不假定內容確實修改。
- OCR 前新增字形輪廓檢查，對高相似度但受抗鋸齒／壓縮影響的候選降噪；未新增 LOGO 或文件白名單。OpenCV 一次搜尋平移，再以完整重疊區確認相關係數，取代 121 次 Python／NumPy 大陣列運算。
- 同一份內容僅移位／換行時，不當成原生文字修改。表格的欄列內容對應仍由既有表格差異流程處理，並未以整頁數字集合取代。
- 保留文字／數字的精確位置，取消把它們放大融合至整個視覺區域；限制影像框合併高度、間距及填充率，整理巢狀重複候選並保留證據。
- 一組完整 Version／Control No 可去除同區局部重複讀值；頁尾保護路徑在字形降噪前執行，未採用會漏掉 Control No 的全頁配準原型。
- 新增容量 256 筆的程序內 ROI OCR 快取；只重用完成的辨識結果，逾時與失敗仍會重試。像素快取改版為 `pixel-v11-glyph-protected`，避免重用舊候選。
- 匯出的標註 PDF 只標內容項目；Excel 的 `diffs` 與 `uncertain_regions` 分頁分開。JSON／PDF 審核報告另列內容與待確認數量，完整證據仍保存。

## 相似字元保護

補查發現輪廓容差會掩蓋「未 → 末」等單字元細微差異，因此低輪廓量的候選不使用新增的降噪捷徑，必須保留到 OCR；新增五組相似中文字與否定詞的候選保護測試。這些測試證明降噪階段保留訊號，不代表後續 OCR 一定能正確辨識或完整列出每個字元修改。

首輪 v10 曾測得約 22% 耗時改善；補上這項保護後最終 v11 為約 17%，以以下數據為準。第一次切換後補查發現此問題，已暫時回復既有映像，再完成保護修正與重新驗收。

## 真實 PDF 驗收與速度

同一台 MacBook Air M4、同一 Docker ARM64 正式基底映像，依序測修改前／修改後；各案例冷／熱快取各一輪。下表是**初步＋完整差異引擎**時間，未含上傳、解析、快照與匯出，亦非 OCI 使用者端總延遲。

| 案例 | 修改前冷快取（秒） | 修改後（秒） | 耗時改善 |
| --- | ---: | ---: | ---: |
| 鳳守愛 | 3.13 | 3.31 | 慢 0.18 秒（約 6%） |
| 慈愛微型 | 20.04 | 16.77 | 16% |
| 新扶愛 | 25.51 | 19.01 | 25% |
| 美保發 | 7.38 | 6.73 | 9% |
| 美利保 | 27.28 | 24.05 | 12% |
| 臻美利 | 14.92 | 11.76 | 21% |
| 心動溢生 | 21.97 | 17.83 | 19% |
| 金放心 | 30.69 | 25.82 | 16% |
| **八組合計** | **150.93** | **125.27** | **17%** |

冷／熱兩輪均保留固定 18／18 個必抓錨點；11 項禁止文字模式、9 項禁止解讀／區域負例均無命中。心動溢生 LOGO，以及金放心 P1 核備文字、P3「給付年繳應繳」不再出現在結果框內。既有 `24 → 28` 與完整頁尾保持可辨識。

修改後心動溢生是 1 個內容項目＋5 個待確認區域；金放心為 1＋9。待確認數可能因解除大片合併而增加，不能把總框數下降當成準確率證明，也不能把這些區域當成已確認的文字修改。

後端 182 項測試通過；前端 production build 通過；獨立 Chrome、模擬 API 搭配真實 PDF 完成統計、預設收合、展開／收合、信度文案與無頁面錯誤檢查。原始量測與限制見 [`content_review_docker_20261015.json`](../benchmarks/results/content_review_docker_20261015.json)。

## 邊界與未採用的實驗

這次改善了三個已知未變區域的誤報及固定樣本耗時，**尚未解決影像型 PDF 全部文字／表格儲存格的可靠擷取**。六組舊錨點中仍有允許以待確認框命中的項目；18／18 不代表全部內容已 OCR 成功，更不是整體 precision／recall 或零漏報證明。

大區塊 Tesseract TSV 加上第二次 OCR 的實驗，仍會因裁切、重排及錯讀製造假新增／刪除；已移出正式程式，未以它宣稱文字召回改善。全頁配準原型也未納入，避免破壞完整頁尾讀值。後續若改用更完整的區塊／表格辨識，須另建立逐項人工真值，驗收數字與欄列對應、文字否定詞、真正新增刪除及未變內容。

既有審核紀錄不會重算；舊報告需重新比對，才會套用新判定。

## 重現

```bash
PDFCHECK_BACKEND_ROOT=/app python /repo/backend/scripts/benchmark_content_review.py \
  --repo-root /repo \
  --output /results/content-review.json \
  --label content-review --save-reports --verify
```

在 backend 正式依賴映像內掛載唯讀 `/repo` 與可寫 `/results`；來源 PDF 需依 `benchmarks/golden/v2/manifest.json` 放置，不隨 Git 提交。部署狀態與回復點以工程歷程及部署驗證檔為準。
