# 商品 DM 接續驗收

日期：2026-10-16。**驗收未通過，不具備以文字／數字完整辨識為前提的上線條件。** 本輪沒有更動正式差異引擎或 OCI；新增可重跑的驗收工具、局部人工真值與結果紀錄。

## 範圍與環境

指定的 `商品DM` 共 16 份不同 SHA-256 的 PDF、8 組新舊版本、合計 80 頁，全部沒有可擷取的原生文字層。使用 `c1d76c6` 工作樹中的 `f357aec` 差異引擎；本輪是 macOS ARM64／Python 3.12.8／Tesseract 5.5.1／PyMuPDF 1.27.2.3。Docker 啟動停在 macOS 權限確認，未修改系統權限設定；沒有將本輪當成正式 Docker 映像或 OCI 驗收。

所有運算使用 `tmp/dm-acceptance-20261016` 內的獨立 runtime 與快取，未清理或改寫正式資料、審核紀錄，未上傳來源 PDF。本輪也沒有測試完整上傳、快照、匯出與 UI 流程。

## 已核實的問題

1. **美利保 P3 利率失去小數點與單位。** PDF 實際為 `3.95% → 4.00%`，報告卻列 `395 → 400`。`_compact_numeric_ocr_pair("3.95%", "4.00%")` 可直接重現同樣錯誤；該函式以 `re.sub(r"\D", "", ...)` 取純數字，最後直接回傳純數字，破壞原始數值尺度。這不是 PDF 的真實內容。
2. **美利保 P4 同文 OCR 誤報。** 「進食障礙／移位障礙、須別人協助才能取用輔具／由床椅」兩版相同，卻因 OCR 讀成「障擬、輔只、肥引人」等字而列為修改。本機甚至因漏讀條列編號而列為數值修改；昨日 Docker 結果也將同區列為文字修改。
3. **慈愛微型 P3 表格移位造成錯誤替換。** 所得清單與「家庭成員投保適用」兩版都存在，表格重排使同一座標落在不同列，卻被列成兩者互相替換。真正新增的第 10 點新住民資格與註解只落在整表待確認框。
4. **新扶愛 P4 注意事項移位造成兩筆錯配。** 兩版第 1 至第 7 點內容均存在，區塊位置因版型改動而下移；報告將第 3 點與第 1 點相配，以及「故不受存款保險之保障」與累計投保金額說明相配。頁面對照可確認這些不是兩組文字的替換。
5. **美保發 P4 頁尾重複。** 完整 Version／Control No 與殘缺 Control No 各列一次。殘缺舊讀值為 `2312-2512-0P2`，完整為 `2312-2512-OP2-0300`，目前依字串包含關係的去重無法處理 `O/0` 錯讀。
6. **心動溢生 P1 兩項真修改沒有內容讀值。** 新增核備文號 `1142320096`，以及「須扣除已領取之各項保險金總額」，都只有待確認框。不能以框到整區當成文字已辨識成功。

心動溢生 LOGO、金放心 P1 核備同文與 P3「給付年繳應繳」三個原指定誤報區域，本輪仍通過禁止區域檢查。這三項改善沒有抵銷以上內容錯誤。

## 根因與接續修正條件

- **數字格式不可破壞。** 保留小數點、正負號、百分比與單位；不能把純數字 compact 值直接當原文。修正後必須保留 `24 → 28`，並禁止把殘缺尾數當完整數值。
- **先找內容對應，再比較文字。** 目前局部 OCR 以同一個矩形讀新舊頁面，沒有先解決移位／換行後的欄列對應。單純降低字串相似度門檻，會把不相干但各自可讀的段落誤判成修改。需以區塊／欄列／閱讀順序對齊，分別驗證真正新增、刪除及移位。
- **可讀字串不等於可靠修改。** 現有 OCR 閘門依字元長度、數字及文字差距推定可靠，沒有證明新舊讀值都正確。不能僅把這些已知誤報移入待確認就宣稱召回改善；仍須讀出上述真修改並通過同文負例。
- **頁尾以欄位與位置去重。** 在同區完整欄位已成功辨識時整理殘缺候選，避免全域把 O／0 混用，也不可刪掉另一個真正不同的欄位。

正式切換前，需以同一 Docker 映像重跑本輪新增真值，修復失敗項目，並完成 OCI 同版驗收。本輪不新增全面文字／表格辨識已完成的宣稱。
