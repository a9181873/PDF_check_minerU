## 效能觀察

成功請求的容器時間戳顯示，首份文件完成後至最後一份完成為 345.44 秒；此區間涵蓋其餘 11 份 PDF、54 頁，換算約 **6.40 秒／頁、9.38 頁／分鐘**。這是模型已載入後的觀察值，包含逐份請求之間的腳本處理成本。

本次腳本未記錄首份請求開始時間、各策略計算耗時、CPU 峰值與記憶體峰值，因此無法提供整批端到端精確耗時，也不能與既有 MinerU＋Docling 流程做公平的效能倍數比較。後續基準測試應將冷啟動、PDF 解析、差異演算法分開計時，並同步記錄 CPU、RSS 與快取命中率。

## 問題與修正

第一次執行時 6 組案例皆收到 MinerU API `409 Conflict`。容器日誌確認根因為 `ModuleNotFoundError: No module named 'six'`；手動補裝後重跑即成功。正式修正已在 `mineru/Dockerfile` 明確安裝 `six`，避免映像重建後再次失效。

辨識結果仍有兩類需持續追蹤的 OCR 噪音：`5/10/15` 被辨識為 `51015`，以及電話／商品名稱區塊被錯誤對齊。就本批資料而言，建議保留 `hybrid` 作為預設候選策略，並以人工標註集驗證 precision、recall 與 F1 後再定案。
